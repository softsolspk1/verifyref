=====================================================================================
1. HOW THE SIMILARITY REPORT WORKS NOW
=====================================================================================

The Similarity Report is made inside the Full Screening Report. It runs side by side with
Module 1 (the reference checks), so it does not wait for them.

Step 1  Prepare the text
        The manuscript is split into words. Quotations and the reference list are marked.
        In-text citations such as [12] or (Smith et al., 2020) are ignored, so a copied
        sentence whose citation was changed is still one match.

Step 2  The PJPS text repository
        The text is fingerprinted and compared with:
          - about 3,700 published papers and web pages kept by earlier checks, and
          - the PubMed Central bulk repository on R2 (588,300 papers when today's two
            reports ran; 838,300 since the publish at 1:01 pm today).

Step 3  Papers on the same subject
        Open-access full texts on the same topic are read and compared with the whole
        manuscript.

Step 4  Passage search
        The text is cut into 8-word passages. Every passage not matched yet is searched as
        an exact phrase, in this order:
          1. Europe PMC (open-access full texts and all PubMed abstracts)
          2. OpenAlex (publisher full texts)
          3. Wikipedia
          4. The open web (Brave Search)

Step 5  Matching
        Every source found is compared word by word with the manuscript. Lightly reworded
        and paraphrased sentences are matched and marked "paraphrased".

Step 6  External similarity service (paid per scan)
        Runs only when the editor ticks the box, or when the in-house Similarity Index is
        15% or more.

Step 7  Scoring
        Every matched word is credited to one source only, so the source percentages add
        up to the Similarity Index (as in Turnitin).

Time limit: on Vercel one run of a job has 240 seconds, and the similarity search stops 30
seconds before that so the report can be saved.

     the bulk repository this would happen more and more often.
  d) No search errors, the PMC repository was used, and no paid credits were spent.


=====================================================================================
3. THE THREE FIXES (MADE 8 NOVEMBER 2026, NOT YET DEPLOYED)
=====================================================================================

FIX 1 - THE SIMILARITY SEARCH CONTINUES OVER SEVERAL RUNS

  Before: when the 240-second limit was reached, the report was saved with whatever had
  been searched.

  Now: when the time limit stops the search, the job hands over to its next run instead of
  saving. The next run starts as soon as the browser checks progress again (about one
  second later). Searches already made are cached, so each run gets further. The parts
  already finished (Module 1 references, cited journals, novelty, author identity) are
  kept and not run again.

  - Up to 4 runs for the similarity search (about 16 minutes at most).
  - If the search is still not finished after the 4th run, the report is saved as before
    and says so: "Time limit reached: N of M passages were searched".
  - A job may now have 8 runs in total (was 6), so waiting for Module 5 in the browser
    and the extra similarity runs fit together.
  - The progress line shows, for example, "Similarity: 210 of 629 passages searched - the
    search goes on in the next run", then "Resuming...".
  - The desktop app and a local server have no time limit, so nothing changes there.

FIX 2 - MORE PAPERS FROM THE PJPS TEXT REPOSITORY

  Before: at most 12 papers from the repository (PJPS-kept papers and the PubMed Central
  bulk repository together).

  Now: at most 30 papers. The desktop app's request to the web platform for repository
  papers was raised from 12 to 30 in the same way.

FIX 3 - THE EXTERNAL SERVICE IS DECIDED ONLY ON A COMPLETE IN-HOUSE SEARCH

  Before: the 15% threshold was applied to whatever the in-house search had found, even
  when the time limit had stopped it.

  Now:
  - While more runs are left, the external decision waits until the in-house search is
    complete.
  - If the external scan is still running when a run ends, the next run waits for it.
    The same scan is found again by its text, so it is never sent (or paid for) twice.
  - If the search is still incomplete after the last run, the external service is NOT
    run on the low, incomplete index. The report says instead:
      "not decided for this report: the in-house search was stopped by the time limit
       (N of M passages searched), so its Similarity Index (X%) is incomplete - run the
       report again to finish the search, or ask for the external comparison"
  - When the editor ticks the external comparison box, it still runs in every case.
